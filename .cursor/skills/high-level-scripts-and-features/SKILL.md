# High-Level Scripts & Features Guide

**Role of this skill:** choose a script by **feature** and see **what data it populates**.  
**Canonical command catalog:** **`docs/Tracking-all-sites-commands.csv`**. Names must match **`package.json`** / Jenkins.  
**Agents coding the framework:** use **rules-md** + **framework-standards**, not this file as the wiring guide.

This document describes what each script does and what data it fills—no deep implementation detail.

---

## What This Framework Does

The automation framework **populates data across multiple features and across multiple orgs (AOs)**. You run scripts to:

- Create users, content, assignments, certifications, dashboards, and more.
- Target a single org (via URL) or many orgs (presales, proservices, platform eval, or all sites).
- Run one script or a chained set (e.g. `cronJobCommand`) to refresh demo data on a schedule.

**To find which script to run:** use the [Quick reference: Feature → Script](#quick-reference-feature--script) section, then look up the script in the detailed sections below.

**Cross-site tracking sheet:** **`docs/Tracking-all-sites-commands.csv`** lists commands with prerequisites and narrative descriptions (for PM/CS spreadsheets).

**Using AI agents in Cursor:** Use **`.cursor/rules/framework-structure-and-skills.mdc`** for skill list and order, **`.cursor/skills/rules-md/SKILL.md`** for code framework layout, **`.cursor/skills/how-to-use-automation/SKILL.md`** for how to run automation, and **`.cursor/skills/automated-features-summary/SKILL.md`** for the full command list.

## Jenkinsfile – High-Level Overview

### How Jenkins runs scripts

- **Manual run:** You pick **url** (optional), **command** (npm script name), **singleOrMultipleOrgs**, and optionally **sitesFilter** or **test** (custom command override). Config is loaded from `./config/${environment}.json`; for single org, the pipeline updates that config with the chosen url, org id, and admin credentials, then runs the selected command inside Docker.
- **Cron run:** Triggered on a schedule (see cron expression in pipeline). Runs only on **develop** branch. For the current day/hour, it gets the mapped org from `jenkins-config.json`, updates config, then runs each command in **commandInfo** (with its timeout and counter). Used to keep demo data fresh across many orgs.

### Parameters

| Parameter                | Purpose                                                                                                                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **url**                  | Org URL (e.g. https://presales1.percipio.com). Required for single-org runs; used to set org id and config.                                                                                                                      |
| **adminUsername**        | Admin email for org login.                                                                                                                                                                                                       |
| **adminPassword**        | Admin password.                                                                                                                                                                                                                  |
| **environment**          | Config environment: `prod`, `dev`, or `preval`.                                                                                                                                                                                  |
| **command**              | npm script to run. Dropdown lists a large subset of package.json scripts (see note below).                                                                                                                                       |
| **singleOrMultipleOrgs** | Where to run: `TriggerInSingleOrg` (use url), `presalesParentSites`, `allParentSites`, `presalesChildSites`, `presalesAseries`, `presalesBseries`, `TriggerInProservicesSites`, `TriggerInPlatformEval`, or `TriggerInAllSites`. |
| **sitesFilter**          | Optional comma-separated site names (or URLs) to limit multi-org runs to those sites.                                                                                                                                            |
| **test**                 | Optional override: custom test command instead of `npm run &lt;command&gt;`. Do not set both **command** and **test**.                                                                                                           |

### Single org vs multiple orgs

- **TriggerInSingleOrg:** One org from **url**. Pipeline updates config for that org and runs the chosen **command** (or **test**) once.
- **presalesParentSites / allParentSites / presalesChildSites / presalesAseries / presalesBseries / TriggerInProservicesSites / TriggerInPlatformEval / TriggerInAllSites:** Pipeline filters orgs by site type, optionally applies **sitesFilter**, then runs the same **command** for each org in sequence (config updated per org, reports preserved per org). EU/US LX Studios course commands run once; the spec iterates orgs internally. **`presalesParentSites`** = `presales1`–`presales25`. **`allParentSites`** = those 25 plus `akara`, `percipiocore`, `percipiodemo`, `platformtest`, `contenteval`, `federal`, `learnvantagedemo`, `smbsandbox`.

### Cron

- Cron runs only when the build is triggered by the schedule and only if branch is **develop**. It uses **commandInfo** in `testData/jenkins/jenkins-config.json` to decide which commands run, how many times each, and with what timeout. Typical commands include activity dashboard, badges, skill benchmark (multiple variants), skills discovery, executive dashboard (desktop and mobile), and view count increase.

### Note on script coverage

- The Jenkins **command** dropdown lists many but not all package.json scripts. Two scripts exist only in package.json and are **not** in the Jenkins dropdown: **editUserInChildSiteSites**, **editUserInChildSitePlatformEval**. For those, run locally with `npm run editUserInChildSiteSites` or `npm run editUserInChildSitePlatformEval`, or use the **test** parameter in Jenkins to run a custom command.

## Summary

- **Package.json:** Contains the full set of scripts; each script does one main job (create/edit data for a feature or cleanup).
- **Jenkins:** Runs those scripts for one org or many orgs, with config and credentials from parameters and from `config/*.json` and `testData/jenkins/jenkins-config.json`.
- **Use this doc** to see what each script does and what data it populates, and to choose the right script when you need to populate a feature or org.
